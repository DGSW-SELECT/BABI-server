# 로그아웃과 회원탈퇴

두 API는 `Authorization: Bearer <accessToken>`이 필요하다. 기존 가입·로그인 응답은 변경하지 않는다. 현재 서버에는 리프레시 토큰이 없다.

- `POST /auth/logout`: 본문 없이 호출한다. 현재 액세스 토큰의 해시를 남은 유효기간 동안 Redis에 보관하여 재사용을 거부한다. 다른 로그인 세션은 유지된다. Redis 장애 시 503이다.
- `DELETE /auth/account`: `{"password":"현재 비밀번호"}`. 인증된 사용자의 비밀번호를 확인한 뒤 계정을 WITHDRAWN으로 표시하고 이메일·비밀번호·닉네임을 익명화한다. 기존 아기 보호자 행은 소프트 삭제하고 권한은 제거한다. 대기 중 가족 및 이메일 초대는 취소한다. 다른 보호자가 남아 있는 아기의 유일한 OWNER는 먼저 권한을 이전해야 한다(409 `ACCOUNT_OWNER_TRANSFER_REQUIRED`). 아기 소유자가 혼자였던 아기 데이터는 삭제하지 않고 보존한다.

탈퇴한 계정의 모든 토큰은 계정 상태를 확인하여 거부한다. 인증된 요청은 Redis와 사용자 DB를 함께 확인하며, 둘 중 하나를 사용할 수 없으면 인증을 실패 처리한다. Redis의 로그아웃 기록이 유실되면 아직 만료되지 않은 로그아웃 토큰이 다시 유효해질 수 있다. 운영에서 로그아웃 보장을 위해 Redis 데이터 보존·복구 정책을 마련해야 한다. 저장소에는 원본 토큰을 저장하거나 출력하지 않는다.
